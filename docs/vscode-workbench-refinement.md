# 作業画面の密度を下げる

VS Code の [UI 構成](https://code.visualstudio.com/docs/editing/getting-started/userinterface) と [Views ガイド](https://code.visualstudio.com/api/ux-guidelines/views) を参照。左の細い Activity Bar、タブ付きエディター、補助パネル、コマンド検索を基本にする。短いビュー名、重複機能を避けること、ボタンを増やしすぎないことを適用した。

前の画面は、常時ラベル付きの太いバー、丸いカードの隙間、大きな見出し、モード切り替えと保存・書き出しボタンの常設が重なり、本文より操作部品の存在感が強かった。

## 変更

- 作業画面をフラットな枠へ変更。上部66→38px、左バー78→48px。
- 上部のモード3ボタンと保存点・書き出しをメニューへ移動。中央にコマンド検索。上部の主操作は8→3個（作品名・ホームを除く）。
- 左はアイコンのみ。名称はツールチップとアクセシブル名で維持。
- 大きな明朝見出しを小さなパンくずへ変更。パネル内の重複見出しと英語の飾りを非表示。
- ビュー名を「ファイル」「レンズ」「検索」に短縮。章の詳細を「くわしく」に変更。
- 検索の置換欄を「おきかえる」の開閉式へ。AI読み手は5ボタンから1選択欄へ。
- パネルの補助操作はホバー／キーボードフォーカス時に表示。既存ショートカット、ドッキング、原稿設定、AI送信確認を維持。

## 確認

型チェックと17ファイル53テスト成功。renderer build成功。隔離プロファイルの実アプリでフラットな画面、置換欄の初期折りたたみ、操作メニュー、メニューから執筆配置への切り替えを確認。メニュー文字の縦折り返しを実画面で発見・修正・再確認した。検証用原稿のみ使用し、実原稿や外部AI送信には触れていない。
