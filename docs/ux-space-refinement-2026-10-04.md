# 執筆画面のスペースと操作の整理

常時表示する情報量、操作までの距離、狭い画面での収まり、キーボード操作を合わせて見直した。本文の読みやすい幅と文字サイズは維持し、周辺の操作領域を整理した。

| 観点 | 判断・変更 |
| --- | --- |
| 本文の面積 | 操作ボタンの絶対配置をやめ、スクロールするタブと固定の操作を同じ一段に配置。上下の本文余白を36pxから20pxへ減らし、分割時の左右余白も幅に応じて調整。 |
| 操作頻度 | 本文検索は直接押せるボタンへ。章の追加・取り込みはパネルのタブ行へ集約し、空の見出し行を削除。 |
| 章が増えた場合 | 章の行高は実測約41pxから30pxへ。長いタイトルは省略表示と全文ツールチップを併用。選択中のタブは切り替え・リサイズ時に見える位置へ戻す。 |
| 検索の見通し | 大文字・小文字オプションを検索欄と同じ行へ。結果を章別にまとめ、章名の繰り返しを削減。一致なし・検索範囲を明示。IME確定のEnterでは検索しない。 |
| 必要なときだけ使う情報 | 置換は既存の折りたたみを維持。保存点どうしの比較も折りたたみ、一覧を優先。レンズ入力の二重の枠・余白を削減。 |
| ホーム | 大きな装飾パネルを外し、「続きから」「新しい作品」「別の作品を開く」を一つの作品一覧へ集約。 |
| 分割・キーボード操作 | パネル内の操作メニューは利用可能な幅・高さに制限してスクロール。Escapeで閉じて起点へフォーカスを戻し、外側クリックでも閉じる。キーボードで別グループへ入った場合もそのグループを操作対象にする。 |
| 初期配置 | 新規・執筆プリセットでは本文へ約82%の横幅を割り当てる。保存済みのカスタム配置は保持する。狭い章パネルには操作が収まる最小幅を設ける。 |

本文設定を一律に小さくする方法や、検索をすべてメニューに移す方法は採用しなかった。読みやすさと操作の見つけやすさを保つため、周辺の重複を優先して削減した。

## 検証

- ワークスペースとデスクトップのTypeScript型チェック。
- Vitest全31ファイル・105テスト。章別検索結果の件数・各一致の維持、英語の空状態、カスタム配置の保持を追加確認。
- Vite renderer、esbuild main / preloadのproduction build。
- git diff --check。
- 専用の12章の原稿と隔離プロファイルによるElectron画面・操作チェック。1440×920と980×680、長い章名、多数のタブ、左右・上下分割、集中モード、ライト・ダーク、縦書きを確認。
- 実行時の13項目のチェックが成功。IME確定による誤検索の防止、章別の全一致、タブの非重複と再表示、メニューの境界・スクロール・Escape、狭い分割の検索欄、キーボードのグループ切り替えを確認。入力したテスト本文がMarkdownへ自動保存されたことも確認。
