# 物語マップ：調査・設計・使い方

2026年10月4日。KOHON の既存デスクトップエディタへの実装。

## 作家が確認したいこと

「出来事はこの順番で起きたが、読者には回想を途中で見せたい」「笑っている人物の本心は怒り」「ある人物が登場していない間にも心情が変化する」。この三つを、同じ人物・同じ場面を参照しながら整理できることを中心に設計した。

入力を完成させてから可視化するのではなく、場面名だけの構想から始め、執筆と往復しながら計画を足せるようにした。原稿の内容と作者の計画を混ぜず、まだ本文にしていない出来事も置ける。

## 画面の読み方

「構成ボード」では場面カードを筋ごとに並べ、空きマスから作成・直接移動・選択時の編集ができる。[配置して考えるUIの使い方](./planning-ux.md)を参照。

1. 上部で「読者に見せる順」「作中の時系列」を選ぶ。選択している方の順番だけを操作する。
2. 「全体を見渡す」は全場面を画面幅に収める。物語全体の緊張、または一人の感情曲線を選べる。クリックすると詳細側の場面へ移動する。
3. 詳細には、場面カード、物語全体の起伏、表のストーリー、裏のストーリー、人物ごとの曲線と感情・表情の記録を、同じ列順で並べる。
4. 点・カード・メモを選ぶと、その場面を編集できる。本文リンクを設定すれば原稿へ戻れる。
5. 狭いパネルではグラフの下に編集欄を置く。「広く表示」でエディタ上に大きく開く。Escape で戻れる。

本文の章順とマップの順番は独立している。「読者順」は構成の計画であり、本文ファイルや書き出しの順番を自動変更しない。このことを操作領域に明記している。

## 表と裏、強さと方向

|記録|意味|
|---|---|
|表のストーリー|行動・会話・出来事など、読者に見える内容|
|裏のストーリー|隠れた動機・内面の変化・秘密・伏線|
|表の感情|物語内に表現されている感情。自由入力|
|表情・仕草|笑顔、視線、唇を噛むなど、描かれている外見上の手掛かり|
|裏の感情|直接表現されていない本心。自由入力|
|直接書かれていない心情|作者が把握している、その場面での内心|
|求めているもの|その場面での人物の欲求や目標|
|高ぶり・強さ|0＝穏やか、100＝非常に強い。喜びも悲しみも強い状態は高い値|
|快・不快|−100＝不快、0＝中立、100＝快。強さとは別の軸|

感情の数値は作者の構成用の目安。心理診断や客観測定ではない。AIでの自動推測は行わない。物語全体の緊張も、人物の感情の平均から勝手に計算せず、作者が別に記録する。

実線は表、破線は裏。人物を色で区別し、色だけで識別できなくても人物名・「表」「裏」・線種が残る。「表だけ」「裏だけ」も選択できる。

未記入の強さは `null`、穏やかと記録した値は `0`。未記録の場面を通って線をつないだり、感情が変わらなかったと推定したりしない。未記録の区間で曲線を切る。

## 並べ替えと非線形な物語

- 場面カードをドラッグする。前半へのドロップはその場面の前、後半へのドロップは後。
- カードの ← / → ボタン、またはカードにフォーカスして Alt+Shift+← / → でも移動できる。
- 読者順を入れ替えても時系列は保持する。時系列を入れ替えても読者順は保持する。
- 場面カードに両方の順位を併記し、回想がどの位置へ移ったかを確認できる。
- 「回想」「舞台裏」を種類として記録できる。舞台裏にも人物の心情を記録できる。
- 同時刻の場面は同じ時間ラベルを付けられる。ラベルは自由入力で、日付・「三日前」・「1日目の夜」などを使える。
- 横軸は場面の順序。実時間の長さに比例する日付グラフではない。時間ラベルを編集しても自動ソートしない。
- 構想を複製し、戻す／やり直すで比較できる。サブプロット名も記録できる。

## 最初の使い方

「表示 → 物語マップ」、左側のグラフアイコン、または Ctrl+Shift+M（macOS は Command+Shift+M）から開く。

既存の作品なら「章から場面を作る」で、まだリンクされていない章・場面の名前、概要、時間ラベル、人物名を取り込む。本文から感情を推測せず、既存の記入済みメタデータだけを使う。繰り返しても同じ章を重複登録しない。取り込んだ後はマップ側の計画として編集する。

新しい構想なら「場面」で一つずつ追加する。「人物名」で人物を登録し、各場面で「この場面で心情を記録する」にチェックして表と裏を入力する。未登場の人物も記録対象にできる。

## 保存と原稿の保護

- 作品フォルダーの `notes/story-map.json` に UTF-8 JSON で保存。新しいアカウントや外部サービスは不要。
- 通常は変更後 450ms で自動保存。保存中の編集は、その保存が終わったあとに追加で保存する。
- パネルを隠したり別のタブを選んだりしても、作品の編集セッションを保持する。
- 通常の保存、作品切り替え、作品一覧へ戻る、終了、保存点作成では未保存のマップの保存を待つ。
- 書き込みは一時ファイルと rename による atomic save。同一アプリ内の書き込みを直列化し、revision の競合を検知する。
- 保存に失敗しても画面上の変更を保持し、再試行・JSON への退避を提示する。競合時は明示的な破棄確認を経て保存済みデータを読み直せる。
- 壊れた JSON や未対応 schema は空のマップで上書きしない。
- マップを含めて保存点を作り、作品全体の復元ではマップも復元する。復元前の安全な保存点を保持する。旧保存点にマップがない場合は現在のマップを保持する。
- 本文の章が削除されても計画を消さず、リンクが見つからないことを編集欄に表示する。
- 章単位の復元はその章だけに適用し、マップ全体を変更しない。

## 検証

データ検証、二種類の順序、欠損値、保存競合、破損 JSON、保存点復元、保存中の追加入力、失敗後の再試行、undo/redo を回帰試験で確認する。

`scripts/verify-story-map.mjs` は架空の原稿とブラウザ用 API で独立して実行する。順番切り替え、実際のポインタードラッグ、人物フィルター、感情の縦軸、本文リンク、再読み込み、削除からの undo、ライト／ダーク／英語／狭い表示、エディタ本体のパネル切り替えを確認し、`.cache/story-map-verification/` に画面を保存する。ユーザーの作品やデスクトップ設定は開かない。

このブラウザ試験には Playwright と Chromium が必要。Playwright を外部のツール環境から使う場合は `KOHON_PLAYWRIGHT_MODULE` にその `index.mjs` の絶対パスを設定する。既存 Edge を使う場合は `KOHON_BROWSER_CHANNEL=msedge` を設定し、`node scripts/verify-story-map.mjs` を実行する。これらは検証用で、製品の追加依存ではない。

この環境では依存フォルダーが junction のため、pnpm 11 の task runner が `ERR_PNPM_UNSAFE_TASK_RUN_STATE_PATH` で拒否する。依存を入れ替えず、同じ TypeScript・Vitest・Vite・esbuild の実行ファイルを直接起動して検査する。

## 現時点の範囲

難解なミステリー向けの知識・伏線・証言・アリバイ・物証・推理・確認候補は「ミステリー設計」に実装した。[使い方と判定の範囲](./mystery-design-2026-10-04.md)を参照。滞在の時間帯は数値の時刻を指定できるが、感情曲線の横軸は引き続き場面順である。

現在のバージョンは手入力・既存章情報の取り込みで作る構成マップ。実時間の間隔・期間幅での配置、並行世界ごとの独立カレンダー、原稿の自動感情解析、マップの順番を本文へ適用する操作は含めない。JSON 書き出しは退避用で、画面内の JSON インポートは未実装。保存点の差分画面は引き続き本文の差分を表示する。
