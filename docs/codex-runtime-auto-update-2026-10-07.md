# Codexを最新の安定版へ自動更新する

モデル一覧の自動取得に加えて、Codex実行環境の自動取得・更新を追加した。標準モデルはGPT-6 Lunaを維持する。設定の「AI」に「Codexの自動更新」と、現在の版・最新安定版・最終確認日時・更新状態・手動確認ボタンを表示する。自動更新は標準でオン、オフも保存できる。

[公式Codex CLI資料](https://learn.chatgpt.com/docs/codex/cli) が案内する `@openai/codex` の最新安定版を使用する。npmの公式レジストリからlatestと端末用の配布情報を取得し、KOHONのユーザーデータ内に保存する。npm・Nodeの別途インストールや管理者権限は不要。システムのCodex、原稿、ログイン情報は書き換えない。

## 更新と失敗時の動き

- 初回接続とモデル一覧更新時に確認する。通常は最新確認を六時間保持し、失敗後の自動再試行は30分空ける。手動確認は待ち時間を越えて再確認する。
- 端末のOS・CPUに合う安定版だけを取得する。プレリリースには切り替えず、既に新しい版がある場合は下げない。
- HTTPSの公式npmレジストリだけから取得し、リダイレクトを許可しない。配布情報のSHA-512、展開先、ファイルの種類、サイズ、実行ファイルの版を確認する。npmのインストールスクリプトは実行しない。
- 検証済みのディレクトリを完成後に公開し、途中のダウンロードは起動候補にしない。
- AIの回答中、ログイン中、接続処理中には切り替えない。次のAI実行の準備時に空き状態を再確認して接続し直す。モデル一覧と利用状況も新しい接続から取得する。
- 新版との初期接続に失敗した場合は、その版を起動候補から外して以前の実行可能な版へ戻る。停止した旧プロセスの終了通知が、新しい接続を切断しないようにもした。
- 通信・配布検証に失敗しても、現在の実行環境で執筆を続けられる。自動更新をオフにすると自動確認を止め、手動確認は使える。

## 実際の検証

公式配布の0.160.1を実際にダウンロードし、SHA-512の照合と版の起動確認を行った。取得した実行ファイルでApp Serverのinitializeとmodel/listを実行し、七モデルとGPT-6 Lunaを確認した。原稿は送信していない。旧版0.159.3からの更新を想定した検証であり、未公開の将来の版が動くことを確認したという意味ではない。記録は `.cache/runtime-update-live/verified-live.json`。

実際の設定画面で現在0.160.1／最新0.160.1、自動更新のオン・オフの保存、手動確認による確認日時の更新を確認した。設定はGPT-6 Luna・自動更新オンへ戻した。

破損した配布、別の配布元、起動失敗、途中のインストール、オフライン、並行する更新確認、回答中の切替防止、新版との接続失敗からの復帰をテストした。48ファイル222テスト、型チェック、renderer/main/preloadのビルドが成功した。既存のchunkサイズの警告は残る。

最新のモデルや機能の提供範囲はアカウントとサーバーに従う。将来のApp Serverの仕様変更を無条件に保証する仕組みではなく、接続検証と以前の版への復帰で継続利用を支える。自動更新の実配布検証はWindows x64。他のOS・CPUは配布先の選択に対応するが、実機検証は未実施。検証済みの旧版を自動削除する処理は含めていない。
