# 物語マップのジャンル・長編・視点の点検

## 点検の結論と改善

同じ場面を感情グラフ・構成カード・情報の配置・詳細台帳で共有する基本設計は維持した。一方、従来はミステリーという名前の入口、長編全体を一度に描く格子、台帳間を行き来する作業、作者の裏設定が混ざる「読者表示」に改善の余地があった。以下を実装した。

|観点|改善した動作|検証する条件|
|---|---|---|
|ジャンルを限定しない|入口を「情報・伏線」にし、使い方の案内を追加。時間・感情・筋・情報は任意。恋愛の誤解、魔法の条件、歴史の密約を同じデータで扱う|恋愛・ファンタジー・歴史・ミステリーの4例を保存形式の検証と実画面で確認|
|複雑な情報を追う|「関係図」で一つの情報に対する伏線、人物・読者の認識、発言、推理を結ぶ。カードと場面名から編集へ移動。12件単位で表示|6種の参照を表示し、キーボードで伏線の詳細を開く|
|作者と読者の情報を分ける|独立した「読者プレビュー」を追加。表の出来事・表情・表の心情・記録された読者の認識・提示済みの伏線を表示|真相・裏の出来事・隠れた心情・欲求・伏線の本当の意味・舞台裏での取得を表示しない|
|長編の移動|感情グラフと両ボードの詳細を24場面単位で表示し、全場面から直接移動。ボードの行も24行単位。感情の俯瞰グラフは全場面を表示|180場面・30人物・30筋・120情報/伏線で表示数、遠方への移動、範囲をまたぐ並べ替えを確認|
|知識の正確さと処理量|視点別に知識更新を索引化し、二分探索で参照。読者順と作中時系列、同じ場面内の記録順を保持。未記録と「知らない」を区別|旧集計との一致を逆順・500更新・参照欠落を含めて照合。最初の範囲の認識が145場面目でも引き継がれる|
|筋の整理|筋の改名・既存の筋との統合・未設定への解除を一回の取り消し可能な操作にする|場面のID、表裏の内容、双方の順番を保持。空の筋の改名と取り消し、保存上限での改名も確認|
|編集中の保存|空の場面名は入力中の下書きとして扱い、保存済みの名前を空にしない。空のまま離れると元の名前を表示|自動保存の待ち時間を超えて空欄にしても保存エラーがない|
|小画面・テーマ・入力|図には線と関係を言葉でも示す。選択中のタブのホバーで文字が背景と同化する問題を修正。詳細の入力は選択した記録だけ展開|日本語/英語、ライト/ダーク、380×640で編集・移動。選択中タブのホバーの文字コントラスト4.5以上|
|負荷と位置の保持|必要になった画面を遅延読み込みし、構成・情報・関係図・読者プレビューの選択を画面切り替えで保持|既存の保存・取り消し・台帳への移動を継続して確認|

## 設計の参考と判断

Aeon Timelineの[フィクションを構想する公式ガイド](https://www.aeontimeline.com/getting-started/planning-fiction-from-scratch)は、作者が使う順番に合わせて計画することを案内している。本実装も日付の入力や特定のジャンル・幕構成を前提にせず、時系列と語る順番を独立に扱う。

Scrivenerの[Binder・Corkboard・Outlinerの公式解説](https://www.literatureandlatte.com/blog/integrating-scriveners-binder-corkboard-and-outliner)を参考に、同じ記録を目的に応じた表示で扱う。図のために別の記録を複製せず、場面や情報のIDを保って詳細へ移動する。

W3Cの[非テキストのコントラストの解説](https://www.w3.org/WAI/WCAG21/understanding/non-text-contrast.html)を踏まえ、線だけ・色だけに意味を預けない。今回の関係図には関係の説明、伏線の配置には段階名、認識には状態名を表示する。完全なWCAG適合を宣言するものではない。

## 実装と検証の境界

「読者プレビュー」は作者が記録した計画の確認用で、本文から情報を抽出したり、実際の読者の理解・気づき・感情を予測したりする機能ではない。情報名と表の記録そのものには作者が読者に見せてよい内容を入力する。伏線の初読の印象は表示するが、本当の意味は自動で表示しない。舞台裏の場面は作者用の計画として保持し、読者の認識には加算しない。

関係図の線は作者が設定した参照を示す。発言の真偽や感情の意味を自動で断定しない。物語内で人物に生じた認識と読者に提示した情報は別に記録できる。関係図は中心の情報に関連した参照を示し、推理同士の依存関係は既存の「推理」のグラフと配置ボードで確認する。

範囲表示はデータを省略・削除する処理ではない。挿入境界と番号は物語全体の順番を使用し、遠方の場面は移動先の指定で選べる。片方の順番を変えてももう片方と本文の章順は保持する。詳細の台帳・居場所図などは用途ごとの別表示であり、保存上限の全組み合わせで性能を保証しているわけではない。

ブラウザ検証は `scripts/verify-story-map.mjs`、例は `fixtures/planning-genres.ts`、知識集計と筋の操作の検証は `apps/novel-editor/src/shared/planning-views.test.ts`。既存のドラッグ・感情編集・本文リンク・引用照合・アリバイ・推理・競合を含む保存と取り消しの検証も維持する。すべてのジャンルの作家にとって使いやすいという実証は、実際の作家による利用評価が別途必要。今回はジャンルに依存しない構造、複数ジャンルの例、規模、視点、保存、入力方法の観点で実装を改善した。

最終確認では、37ファイル・155テスト、ルートとアプリの型チェック、renderer/main/preloadのビルド、元のワークスペースでのブラウザ検証が成功した。ブラウザエラーは0件。範囲の境界でのキーボード移動・取り消し、編集途中でのフォーカス保持、関係図の中心と読者プレビューの読む位置の保持も確認した。画像は `.cache/story-map-verification` に保存する。
