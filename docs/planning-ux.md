# 物語を「配置して考える」ためのUI

## 評価と設計判断

以前の画面には、感情曲線・伏線・知識を管理する機能があった。ただし、伏線の位置を変えるにも台帳へ移動して場面を選び直し、多数の入力欄を読みながら操作する必要があった。全体を見渡す表示と編集する表示が離れていることが、操作上の弱点だった。

改善の中心は、同じデータを構成ボード、配置ボード、感情グラフ、詳細台帳で共有すること。見た目の変更に加えて、空きマスからの作成、配置の直接移動、視点の切り替え、選んだ記録への詳細表示を実装した。利用者全員にとって直感的かは実際の作家による評価が必要だが、ブラウザでは以下の操作が成立することを確認する。

## 構成ボード

「物語マップ → 構成ボード」で、筋・サブプロットを縦、場面の順番を横に並べる。

- 空きマスを押すと、その筋、その位置に場面を作る。もう一方の順番には末尾へ追加する。
- カードを移動すると、選択した読者順／時系列の位置と所属する筋を変更する。カードの左半分に落とすと前、右半分なら後へ入る。
- ドラッグの代わりにカードの矢印、Alt+Shift+←／→、編集欄の「所属する筋」を使える。
- カードを選ぶと、場面名・表の出来事・裏の動き・緊張を同じ画面で編集する。「感情・表情も詳しく編集」から該当する場面のグラフ・感情編集へ移動する。
- 人物や検索でカードを絞る。非表示になった場面の列は詰めないため、配置変更で隠れた場面を誤って飛ばさない。
- 「小さく一覧」で、構成を俯瞰しやすいカードサイズに切り替える。
- 名前だけの筋も保存する。場面をまだ置いていないサブプロットを構想できる。

人物フィルターは感情を記録した人物との対応を使う。登場人物を本文から推測する機能ではない。場面の原稿の章順は自動で変えない。

## ミステリーの配置ボード

「情報・伏線」を開くと、まず配置ボードが表示される。「配置するもの」で四つの表示を切り替える。ジャンル共通の関係図、読者プレビュー、長編の範囲表示については[ジャンルと長編の点検](./planning-audit.md)も参照。

|表示|ボードで直接できること|広がる作業|
|---|---|---|
|伏線|提示・再解釈・回収を別々に置き、移す。初読の印象と本当の意味を編集する|回収を先に決めて伏線を逆算する。複数回の提示を比較する|
|知識|情報と場面の交点で、読者・人物の認識を記録する。認識を引き継いだ区間を区別して表示する|誰にはいつ分かっているかを比較し、意図した誤解を設計する|
|物証|場面で所持・保管・施錠・解錠・破壊・所在不明を記録し、所持者を変更する|鍵や手紙が移る順番を構成と照らし合わせる|
|推理|推理する場面を置き、前提になる別の推理を接続・解除する|結論から必要な推理を組み立て、循環した根拠を確認する|

記録のチップをドラッグすると、その記録の場面だけを変更する。他の提示、裏設定、引用文、情報源、結論、代替説、場面そのものの順番は保持する。既に同じ場面にある提示へ移した場合は提示を重複させない。同じ場面内の複数の知識更新は、元の記録順を維持する。

チップを選び、編集欄の「記録の移動先」で移すこともできる。Alt+Shift+←／→で隣の場面へ動かせる。「この配置を外す」は配置や、その時点での認識更新を外す操作で、情報・伏線そのものを削除しない。推理の配置を外しても、推理の根拠と結論は保持する。知識更新を外すと、それ以前の認識が引き継がれる。

読者の知識と伏線・推理の配置は読者順、人物の知識と物証は作中時系列で表示する。知識の「未記録」を「知らない」と同一視しない。読者の知識を移しても人物の取得時点は変わらない。

場面がまだない場合は、構成ボードへ進む案内を表示する。引用・情報源・真相・操作条件などの詳細は、その記録の台帳を開く。詳細のカードは通常折りたたみ、作成・選択した記録だけを開く。ボードに戻っても、種類や選択を維持する。

## 保存と取り消し

ボード、グラフ、台帳で別のデータを作らず、同じ `StoryMap` と `MysteryBoard` を編集する。既存の自動保存、変更の競合検知、JSON退避、元に戻す／やり直す、保存点復元を使う。空の筋の名前は任意の `plotlines` 属性に保存する。旧形式のマップには移行操作や必須属性の追加を要求しない。

ドラッグ・クリック・キーボードで登録情報を変えたら、既存の確認候補も同じデータに基づいて更新される。推理の接続で循環を作った場合は、確認候補に表示する。本文の意味やトリックの成立を自動証明するものではない。

## 調査した操作の考え方

公式説明を参照し、同じ情報に複数の表示を用意することと、カードの直接操作を中心に設計した。各製品の有料版を実機比較したユーザビリティ調査ではない。

- [Aeon Timeline — Story timelines](https://www.aeontimeline.com/guides/story/getting-started)：同じ物語情報を異なる表示で参照し、変更を共有する考え方。
- [Aeon Timeline — Guides](https://www.aeontimeline.com/guides)：関係、構成、複数の表示による計画方法。
- [Plottr — Timeline overview](https://docs.plottr.com/article/54-timeline-overview)：場面・筋をカードで配置し、人物などで絞る操作。
- [Plottr — Features](https://plottr.com/features/)：カードのドラッグ、俯瞰、フィルターを使う構成操作。

## 完了を確認する項目

|目的|実装・検証の根拠|
|---|---|
|全体を見ながら操作する|`StoryBoard.tsx` と `MysteryBoard.tsx`、ライト／ダークの描画画像|
|カードを直接動かす|`verify-story-map.mjs` の実ポインタードラッグと、読者順／時系列の独立性検証|
|ドラッグ以外の操作も使える|矢印・筋の選択・配置先の選択・キーボード移動、移動・削除・undoのブラウザ検証|
|作業の幅を広げる|伏線の別々の配置、視点別の知識、物証の所持者、推理の接続と循環検出の操作検証|
|入力欄で全体像を隠さない|選択時の編集欄、台帳の折りたたみ、詳細への遷移と選択維持の検証|
|原稿・既存計画を守る|移動で無関係な記録を保持する `planning-interactions.test.ts`、既存の保存・復元・原稿リンク検証|
|表示が狭くても操作できる|380pxでの外側の横はみ出し検査と、選択時・ダーク表示の描画画像|

画像は検証時に `.cache/story-map-verification/` に作成する。架空の作品だけを使い、実際の作品やデスクトップ設定には書き込まない。
